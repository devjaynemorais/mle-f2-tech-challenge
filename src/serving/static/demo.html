Isto chama o modelo Production de verdade (via MLflow Model Registry) através do mesmo RecommendationService que serve /recommend — não é um mockup com números inventados. Só a etapa final (montagem de features → score → ranking) acontece ao vivo aqui; o resto do pipeline rodou uma vez, offline, antes de qualquer pedido de recomendação chegar.

O pipeline offline (rodou uma vez, antes de tudo)

Estas 6 etapas são o dvc.yaml do projeto — cada uma só reexecuta quando seus inputs mudam (dvc repro). Nenhuma delas roda quando você pede uma recomendação abaixo.

1 · preprocess

2,76M eventos brutos → 948.537 após filtrar usuários com <5 interações (RetailRocketPreprocessor). Split cronológico 70/10/20 — nunca embaralhado.

offline

2 · content

Extrai categoria de cada item de item_properties — alimenta o embedding de categoria (cold-start de conteúdo).

offline

3 · feature_eng

Features causais as-of (só o que era conhecido até o instante do evento): frequency, engagement_score, recency_days, view_count, user_item_view_count, user_item_recency_days.

offline

4 · train

NCF: embeddings (usuário/item 64d, categoria 8d) + contínuas → MLP [128, 64] → duas cabeças (strong/view, multi-task). Negative sampling 8:1, early stopping (patience=5) por val-AUC.

offline

5 · evaluate

NDCG@10/20, Recall@10/20, HitRate@20 por usuário, comparado contra o baseline de popularidade nos mesmos candidatos.

offline

6 · promote

Registra no MLflow Model Registry e promove Staging → Production pela melhor val_ndcg_at_20 entre todos os runs.

offline
